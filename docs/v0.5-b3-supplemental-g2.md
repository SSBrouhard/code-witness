# B3: supplemental G2 knockout attribution

**Status:** post hoc tool correction authorized by the owner on October 23, 2026.
Implementation and validation only. The original preregistered v0.5 attempt remains
**STOPPED on S5**. This document does not amend its historical result or authorize
experimental gate reruns, adjudication session 2, or comparison.

Authority and implementation tracking: [PORT-116](https://linear.app/stephen-portfolio/issue/PORT-116)
and [PORT-125](https://linear.app/stephen-portfolio/issue/PORT-125). The owner requires
fair measurement, without blanket per-item credit for an import failure.

## What changes

The original transform replaces every function body in the target scope with a
dedicated `CodeWitnessKnockout("code-witness knockout")` exception. A target can
call those functions while importing. The original B2 pytest collection mapping
credited every clean item in the affected module as changed, while the witness
worker failed before producing an observation. That format asymmetry is the S5
incident.

B3 retains the transform and 80% threshold, but separates two questions:

1. Did this item execute a knocked-out target function outside import processing?
2. Did its observable outcome change?

Only an affirmative answer to both receives `changed` credit. Import dependency
and target calls during collection or pre-item initialization are reported
separately. These blockers cannot increase the numerator or disappear from the
denominator. Target calls during per-item setup and cleanup can qualify, as
specified below.

## Exact measurement

| Outcome | Witness fixture | pytest item |
| --- | --- | --- |
| `changed` | Its observation differs from the frozen observation, and a scoped runtime knockout was traced during `adapter.run`. | It records an assertion, target-exception or setup/teardown error, and a scoped runtime knockout was traced during that item's setup, call or teardown. |
| `unchanged` | Its complete observation equals the frozen observation. | It passes under knockout. |
| `blocked` | Timeout, or an attributed target knockout prevents execution/comparison through import or pre-item initialization. | Timeout, a qualifying collection blocker, or an attributed import blocker prevents item comparison. |
| `errored` | Worker/protocol failure, non-reproducing pre-item attribution, or an observation change without runtime target evidence. | Missing/unclassified/setup failure without runtime or dependency attribution, missing probe evidence, or a failure without runtime target evidence. |

A **scoped runtime knockout** is a traced exception whose exact type name and
message match the dedicated knockout, whose innermost origin is in a scope file,
and whose first occurrence is during the specific item's execution. An exception
propagating through another target frame is not a new execution event. Importlib
on the origin's stack makes it import dependency evidence even when a test body
has already started. Thus a lazy import-only item cannot gain changed credit
because target initialization failed.

pytest setup and teardown count as part of an item's execution, just as target
setup/cleanup inside `adapter.run` does for a witness fixture. A shared pytest
fixture's failure is not copied as positive evidence to later items: each item
needs its own traced execution event. A cached setup failure without that event
remains unresolved.

The witness probe calls the unchanged engine worker in a fresh subprocess. A
pytest plugin records phase and node ID; a private JUnit property binds an
executed item's result to its trace. Both clean and knocked runs use the same
instrumentation. No engine code, adapter, test, or stored observation is edited.
The pytest trace plugin itself does not import or require the witness engine.

The clean witness replay must match every frozen observation. The clean pytest
replay must exit successfully with only passed/skipped items. Units remain the
stored witness fixtures and the pytest items that passed cleanly; skipped pytest
items are excluded. The same archive/freeze checks and source restoration apply.

A pre-observation witness target knockout must repeat with the same structured
origin/type/message. Pytest collection attribution retains B2's clean-module,
target-origin, non-dependency and repeated-location requirements, but now records
the affected units as blocked instead of changed. An unrelated error, a marker
appearing only in text, or a same-named exception raised by the test/adapter is
not a scoped knockout.

`runtime_evidence` records per-item origin/phase events. `reached_target` is the
number of units with that runtime evidence, including units that swallowed the
exception and remained unchanged. Execution alone does not demonstrate
sensitivity. `dependency_evidence` is separate and never contributes changed
credit. Units stay in the original denominator. The existing `knockout_status`
function is unchanged: at least 80% changed passes; unresolved units that could
decide that threshold yield insufficient evidence; otherwise it fails.

## Bounded implementation and use

B3 is opt-in: `score.py knockout --methodology b3` with the existing suite/scope
arguments. Output identifies itself as `B3-supplemental-post-hoc`. The default
`--methodology original` preserves the historical tool behavior for reproduction.
No result from that default may be relabeled B3.

The changes are confined to the G2 path, its worker envelope, pytest trace plugin,
paired tests and this document. B1/B2 mutation and challenge classifications,
thresholds, budgets, baseline archives, original protocol and comparison logic
are unchanged. The frozen tools and all evidence under `~/cw-v05/` are untouched.
Future authorized supplemental outputs must have new names and retain their B3
provenance. They cannot replace or masquerade as preregistered evidence.

## Validation

`experiments/v0.5-comparison/tests/test_b3.py` creates paired synthetic suites
without reading experimental baselines or evidence. It covers:

- ordinary target execution and observed sensitivity;
- import-only items with and without target initialization;
- deferred imports during the item body;
- explicit collection-time target calls;
- marker-like text, same-named exceptions outside scope, missing dependencies,
  and unrelated collection/runtime failures;
- unrelated hard worker exits;
- caught target knockouts with changed behavior;
- real execution with an unchanged outcome;
- clean restored trees and unchanged sealed synthetic deliverables.
- pytest probe independence from the witness engine and target module names.

The existing suite continues to verify the original/default method and non-G2
scoring. CI runs the new canaries on its existing Python version matrix, alongside
the original synthetic canary preflight. No experimental gate is needed for this
implementation validation.

## Limits and fairness

B3 applies the same attribution and credit rule to both formats. It removes
blanket collection credit and does not convert witness worker failures into
successes. An import-blocked suite may remain insufficient evidence in either
condition. No corrected experimental result is claimed here.

This measures **observed sensitivity to a global function-body knockout, backed
by scoped per-item runtime evidence**. It is not semantic correctness, exhaustive
coverage, or proof that every target operation was exercised. It deliberately
does not credit import initialization, collection-only calls, or source introspection alone.
Caught exceptions can still count when the trace proves runtime execution and
the item's observable result changes; swallowed exceptions with no outcome
change do not count.

Tracing observes the current Python thread/process. Calls delegated to other
threads/processes or native code may lack evidence and cannot receive changed
credit. Code that replaces the trace hook can also remove evidence. The
instrumentation is not a security boundary against a malicious baseline.
Tracing adds overhead while retaining the existing five-second fixture limit
and declared pytest suite timeout; additional timeouts remain blocked, never
successes. Fixture granularity, pytest collection/session state, and the two
formats' different observation channels remain limits on broader comparability.
