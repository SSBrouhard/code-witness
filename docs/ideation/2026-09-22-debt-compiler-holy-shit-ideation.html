Repo-grounded ideation

Make Debt Compiler the thing you run before touching scary code

The winning product is not another linter, refactoring bot, or dashboard. It is an evidence chain that answers one high-stakes question: What did my change alter that we observed, and what remains unknown?

Date: 2026-09-22Topic: debt-compiler-holy-shitMode: repo-grounded

Grounding Context

Debt Compiler already has a credible small core: arbitrary Python gets a static pack, risky syntax gets conservative review tags, and Git archaeology preserves missing history rather than inventing intent. Its dynamic proof is intentionally narrow: trusted batch.py code plus fixtures and a run(case, sleep=...) convention. The current pack observes returns, exceptions, stdout, stderr, and injected sleeps, but not ordinary module entrypoints or external effects.

That leaves a clear gap. Approval tests preserve known outputs, static analyzers surface known patterns, and codemods apply known transformations. None naturally produce a portable, slice-level explanation of what a legacy change must preserve, what is unknown, and what exactly changed in the candidate implementation.

Product boundary: do not promise arbitrary-Python equivalence or safe automatic execution. Every runtime capture must use an explicit adapter, a declared observation boundary, raw evidence, and a visible unknowns list.

1

Explicit replay adapters for real modules

Replace the one hard-coded runtime convention with a tiny, declared adapter. The maintainer names an entrypoint, fixture source, controlled dependencies, timeout, and observable channels. The adapter makes a normal module replayable without pretending that importing an application is safe or that dependencies are understood.

Axis
Onboard ordinary modules
Basis
direct: runtime is currently gated by the exact batch.py, fixture, and run protocol; static extraction already accepts ordinary Python files.
Rationale
It unlocks the tool's strongest capability, behavior preservation, for code developers actually have.
Downside
Adapters are still work. The product must make their limits explicit, not hide them behind "zero config."
Complexity
Medium
2

One-boundary side-effect recorder

Start with one explicit boundary, such as outbound HTTP or database writes, and record normalized events only there. Replay compares the raw event stream as well as return values. Everything outside enabled adapters remains unknown, not silently absent.

Axis
Capture behavioral evidence
Basis
direct: current replay captures returns, errors, streams, and injected sleep only; external: causal profiling demonstrates why an observed path is more useful than a flat function list.
Rationale
Most dangerous refactor regressions are a duplicate charge, reordered write, or accidental send, not a changed dictionary.
Downside
Normalization can hide regressions. Keep raw events and version every comparison policy.
Complexity
Medium
3

Evidence decision table

Turn each replay into a compact table of input condition, observed output, captured events, and unknown boundaries. A failed candidate comparison points to the first differing observed field rather than dumping two blobs of JSON. Keep the lexical graph separate so it cannot be mistaken for runtime proof.

Axis
Explain cause and provenance
Basis
direct: the current graph says its edges are lexical and unresolved, while the harness records fixture-level observations.
Rationale
This is how the artifact becomes legible to a human under review pressure.
Downside
Observed traces are examples, not exhaustive paths. The UI must make that distinction painfully obvious.
Complexity
Medium
4

Mutation-guided contract gap finder

For a high-risk finding, make a small transparent mutation such as changing a rounding mode, retry limit, comparison, or event order. If replay fails, the tool shows the witness. If it survives, Debt Compiler reports the exact unprotected boundary and suggests the smallest missing case. This measures whether the pack discriminates among selected changes, not whether the behavior is fully proven.

Axis
Capture behavioral evidence
Basis
direct: the existing sample catches a timing mutant and exposes a manually added 2.675 rounding boundary.
Rationale
"We deliberately broke the scary line and the contract caught it" is far stronger than a generic coverage number.
Downside
Mutant selection must be deterministic, inspectable, and bounded.
Complexity
Medium
5

Observed-field diff for a proposed refactor

Replay legacy and candidate code through the same adapter and compare named observed fields: return values, exception type and message, stdout/stderr, normalized events, order, and injected timing requests. The result says exactly what changed, what held, and what was not observed. It makes no claim of general program equivalence.

Axis
Review refactor deltas
Basis
direct: current pack diff intentionally misses some candidate output changes when both versions still match their baseline; replay already has a dual-run shape.
Rationale
This is the actual review primitive: did cleanup change an observed field, and where?
Downside
Requires adapters and cannot speak for unobserved effects.
Complexity
Medium
6

Unknowns ledger with next evidence action

Make uncertainty a first-class output. State the unadapted boundaries, unexercised branches, unavailable Git history, and unsupported entrypoints, then rank the smallest next observation that would reduce each uncertainty. “NOT RUN” becomes “add this adapter seam or fixture to verify this exact risk.”

Axis
Onboard ordinary modules
Basis
direct: the tool already preserves NOT RUN and missing history rather than treating unknown as clean.
Rationale
Trust compounds when a tool draws the boundary of its knowledge instead of cosplaying omniscience.
Downside
The suggestions must remain concrete and minimal, or become a guilt-inducing backlog.
Complexity
Low
7

CI tripwire with an intentional-change receipt

Run only on a changed, already-adapted slice. Fail when a must-preserve observed claim changes, when replay cannot run, or when an observation boundary becomes newly unknown. An intentional change is allowed only with a small, committed acknowledgement linking the old witness, new witness, and human rationale. Generate a PR change passport from the same evidence chain.

Axis
Review refactor deltas
Basis
reasoned: portable packs and deterministic comparison already exist; the missing step is an accountable decision gate rather than another report.
Rationale
It operationalizes hard-won knowledge without forcing a full-repository analyzer onto unrelated pull requests.
Downside
Premature rollout would create friction. Ship after adapters, observed-field diffing, and unknowns are trusted.
Complexity
Medium

Rejection Summary

IdeaReason cut or deferred
Automatic safe input discoveryRefuted as stated: arbitrary Python inputs cannot be safely inferred. Reframe as non-executing adapter and fixture suggestions.
Durable behavioral ledgerUseful later, but risks becoming a test dashboard before the per-slice evidence chain earns trust.
Automatic safe extraction boundaryKeep only as a review suggestion. A lexical graph cannot certify a boundary as safe.
Cross-pack debt mapDefer. Aggregates can turn nuanced unknowns into misleading scores.
Generic refactor blast radiusFolded into observed-field diff and PR passport. Raw call-graph reachability is too noisy.
